Java 21 / Spring Boot 4.1 / Spring Cloud 2025.1 / Spring AI 2 으로 일괄 업그레이드합니다.
스택을 올리는 것만으로도 다수의 알려진 취약점(CVE)이 함께 해소됩니다.

직접 선언한 라이브러리뿐 아니라 그 라이브러리가 끌어오는 전이 의존성까지 포함해 취약점을 스캔하고, 1단계 이후에도 남아있는 개별 CVE를 패치합니다.

파이프라인 동작 방식

각 단계가 내부적으로 어떻게 동작하는지 보여줍니다 — 시작한 작업의 실시간 진행 상황이 아닙니다.

Stage 0 — 버전 확인 + 베이스라인 스캔

1·2단계 중 하나라도 선택하면, 실제 마이그레이션/패치에 들어가기 전에 항상 이 게이트를 거칩니다.
현재 버전/스택을 분석하고 출력 버전을 자동 제안한 뒤, 사람이 확인해야 다음 단계로 넘어갑니다.
아래 4단계는 전부 인입 직후의 원본(source/)을 대상으로 실행됩니다
— 실제 변경은 사람이 확인한 뒤 1단계부터 별도의 작업 사본(work/)에서 시작됩니다.

Stage 1 — 스택 마이그레이션

선택한 목표 스택까지의 계획을 스텝별로 세운 뒤, 각 스텝을 "적용 → 검증 → (실패 시) AI 수정 → 재검증"을 자동으로 반복하는 자가검증 루프로 실행합니다.
재시도를 다 써도 안 되면 인수인계 가이드를 남기고 멈춥니다.

Stage 2 — 개별 CVE 패치 (옵션)

전이 의존성까지 포함해 스캔한 CVE 목록을 하나씩, Stage 1과 같은 모양의 자가검증 루프로 패치합니다. CVE들은 서로 독립적이라 하나가 막혀도 나머지는 계속 시도합니다.
