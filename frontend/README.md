# Maven Stack Upgrade Tool — Frontend

백엔드([`../backend`](../backend))의 REST/SSE API만 호출하는 순수 정적 HTML 클라이언트입니다. 빌드 단계가 없습니다 — 백엔드와 독립적으로 배포/수정할 수 있도록 일부러 이렇게 만들었습니다.

## 실행

정적 파일을 아무 HTTP 서버로 띄우면 됩니다. `file://`로 직접 여는 것은 피하세요 — 브라우저가 `fetch`/`EventSource`의 CORS 처리를 오리진이 `null`인 경우 예측 불가능하게 다룹니다.

```bash
cd frontend
python -m http.server 5500
# http://127.0.0.1:5500 접속
```

(VS Code의 Live Server 확장을 써도 됩니다 — 기본 포트도 5500입니다.)

백엔드의 `CORS_ALLOW_ORIGINS`(`backend/.env`)가 이 프론트엔드를 띄운 오리진과 일치해야 합니다. 기본값은 `http://localhost:5500`입니다. 다른 포트/호스트로 띄웠다면 `backend/.env`의 `CORS_ALLOW_ORIGINS`를 맞춰 바꾸고 백엔드를 재시작하세요.

헤더 우상단의 설정(⚙) 아이콘을 클릭하면 뜨는 "설정" 모달에서:
- **API 서버 주소** — 기본 `http://127.0.0.1:8000`
- **API 토큰** — 백엔드 `.env`의 `API_AUTH_TOKEN`을 채워둔 경우에만 입력 (비어 있으면 인증 없이 요청)

두 값 모두 브라우저 `localStorage`에 저장되어 새로고침 후에도 유지됩니다.

같은 모달 안에 NVD/Trivy 취약점 DB의 마지막 갱신 시각과 "지금 갱신"(⟳) 버튼이 있습니다. 스캔은 더 이상 이 DB를 암묵적으로 갱신하지 않으므로(`backend/README.md` 참고), **최초 실행 전에 한 번은 이 버튼으로 갱신해야** 스캔이 의미 있는 결과를 냅니다. 갱신 중에는 아이콘이 회전하고 완료되면 멈춥니다.

## 화면 흐름

1. Git URL 또는 ZIP 파일 중 하나를 선택해 소스를 지정하고, 1/2단계 실행 여부를 선택한 뒤 "작업 시작"
2. `POST /jobs` 202 응답으로 받은 `job_id`로 `GET /jobs/{id}/events`(SSE)에 연결해 진행 로그와 상태를 실시간으로 표시. 1·2단계 중 하나라도 선택했다면 Stage 0(현재 버전/스택 분석 + 마이그레이션 전 취약점 스캔)이 끝난 뒤 상태가 `awaiting_version_approval`로 멈추고, 감지된 현재 버전과 제안된 출력 버전이 진행 패널에 표시됨 — "적용할 출력 버전" 입력창(제안값이 미리 채워짐)을 확인하고 "확인하고 계속" 버튼을 눌러야 1/2단계가 시작됨 (동일 버전으로는 확인 불가 — 사내 Nexus 배포 시 기존 아티팩트를 덮어쓰지 않기 위한 정책)
3. 작업이 종료 상태(success / stage1_needs_handoff / stage2_needs_handoff / failed)에 도달하면 `GET /jobs/{id}/artifacts`로 결과물 목록을 조회해 diff / report / (있다면) AI 인수인계 가이드 버튼을 표시(`stage1_needs_handoff`면 "인수인계 후 재개" 버튼도 함께 표시 — §인수인계 후 재개 참고)
4. 각 결과물은 복사 또는 다운로드 가능
5. 상단 "이력 보기" 링크로 `history.html`에 가면 `GET /jobs`로 지난 작업을 최신순 목록으로 확인하고, 각 job_id를 클릭하면 `job.html?job={id}`에서 해당 작업의 로그 이력(종료된 job은 replay, 진행 중인 job은 실시간)과 결과물을 동일한 방식으로 다시 볼 수 있음

## 수동 스모크 테스트 체크리스트

자동 UI 테스트 프레임워크는 두지 않았습니다(정적 HTML + vanilla JS, 빌드 없음). 백엔드를 바꾼 뒤에는 아래를 수동으로 확인하세요. 페이지/기능별로 묶여 있으니 관련 없는 부분을 바꿨다면 해당 절만 확인해도 됩니다.

### 공통 (설정 모달 · 페이지 이동)

- [ ] 설정(⚙) 아이콘 클릭 시 설정 모달이 열리고, 닫기 버튼 또는 배경 클릭으로 닫히는지
- [ ] 모달을 열었을 때 API 서버 주소 기본값이 채워지고, 이전에 입력한 토큰이 있으면 복원되는지
- [ ] `index.html` / `history.html` / `job.html` 간 이동 링크가 모두 동작하고, 설정 아이콘/모달이 세 페이지 모두에 있으며 연결 설정(API 주소/토큰)이 페이지를 옮겨도 유지되는지
- [ ] 설정 모달에 NVD/Trivy 마지막 갱신 시각이 표시되고, "지금 갱신" 클릭 시 아이콘이 회전하며 상태 텍스트가 진행 로그를 따라 바뀌는지
- [ ] 갱신 완료 후 아이콘이 멈추고 새 시각이 반영되는지, 이 갱신 실행이 `history.html`에는 보이지 않는지
- [ ] 설정 모달을 열면 "LLM 모델" 섹션에 드롭다운이 채워지고 현재 모델이 선택돼 있는지
- [ ] 드롭다운에서 다른 모델 선택 → 별다른 확인 없이 바로 반영되는지(추가 저장 버튼 없음), `backend/.env`의 `LLM_MODEL` 줄이 실제로 바뀌었는지, 다른 줄(예: `OPENAI_API_KEY`)은 그대로인지 파일로 확인

### 새 작업 시작 (`index.html`)

- [ ] Git URL / ZIP 업로드 라디오 전환 시 해당 입력 필드만 보이는지
- [ ] 둘 다 비운 채 제출 시 폼 유효성 에러 메시지가 뜨는지 (요청이 나가지 않아야 함)
- [ ] "새 작업 시작" 폼에서 1단계/2단계 체크박스 아래에 설명 문구가 각각 표시되고, 줄바꿈/정렬이 어색하지 않은지
- [ ] ZIP 업로드로 유효한 Maven 프로젝트 제출 → 진행 패널에 로그가 실시간으로 쌓이고 상태 배지가 `queued` → `running` → 종료 상태로 바뀌는지
- [ ] Gradle 프로젝트(= `pom.xml` 없음) 제출 시 상태가 `failed`로 끝나고 에러 로그가 표시되는지
- [ ] `API_AUTH_TOKEN`을 설정한 백엔드에 잘못된 토큰으로 접근 시 진행 패널에 인증 오류가 표시되는지 (SSE는 쿼리 파라미터로 토큰을 전달합니다 — `EventSource`는 커스텀 헤더를 지원하지 않기 때문)

### Stage 0 — 출력 버전 승인

- [ ] 1단계만 선택해 제출 → Stage 0 완료 후 진행 패널에 "감지된 현재 버전"/"제안된 출력 버전"이 표시되고, "적용할 출력 버전" 입력창에 제안값이 미리 채워지는지
- [ ] 입력창을 감지된 현재 버전과 같은 값으로 두고 "확인하고 계속" 클릭 → 에러 로그가 남고 상태는 계속 `awaiting_version_approval`로 대기하는지 (버튼이 다시 활성화돼 재시도 가능한지)
- [ ] 입력창을 다른 값으로 바꿔 "확인하고 계속" 클릭 → 버전 확인 패널이 사라지고 1단계가 정상 진행되며, "분석" 패널에 마이그레이션 전 취약점 표가 이미 채워져 있는지
- [ ] 1단계 완료 후 "마이그레이션 후" 취약점 표가 채워지는지 — 2단계를 선택하지 않은 job(1단계만)에서도 채워지는지(예전에는 2단계를 선택해야만 1단계 이후 재스캔이 돌았음)
- [ ] 2단계도 선택한 경우 "2단계 패치 대상" 취약점 표가 자동으로 채워지는지(마이그레이션 후 표와 같은 스캔 결과를 재사용하므로 건수가 동일해야 함), 2단계 완료 후 "최종" 취약점 표까지 채워지는지
- [ ] 확인한 출력 버전이 `history.html`의 "출력 버전" 열과 `job.html` 결과물에 정확히 반영되는지
- [ ] 1·2단계 둘 다 선택하지 않고 제출 → 버전 확인 단계 없이(`awaiting_version_approval`을 거치지 않고) 바로 `success`로 끝나는지
- [ ] `awaiting_version_approval` 상태에서 "중지" 버튼 클릭 → 확인 다이얼로그 후 정상적으로 `cancelled`로 끝나는지

### 사내 parent POM(BOM 겸용) 목표 버전

- [ ] 사내 parent(공개 `spring-boot-starter-parent` 등이 아닌 `<parent>`)가 있는 프로젝트 제출 → 버전 확인 패널에 "사내 parent POM 목표 버전" 입력창이 추가로 뜨고, 감지된 parent 좌표/현재 버전이 안내 문구에 표시되는지
- [ ] 공개 parent를 쓰거나 `<parent>`가 없는 프로젝트 제출 → 그 입력창 자체가 안 뜨는지(회귀 확인)
- [ ] 입력창을 비운 채 확인 → 1단계가 기존처럼 진행되고(스택 프로퍼티가 parent 상속이라 대부분 변경 없음), 결과물 리포트에 "이 프로젝트만으로는 목표에 도달할 수 없습니다" 안내 문구가 남는지
- [ ] 입력창을 감지된 현재 parent 버전과 같은 값으로 두고 확인 → 409, 계속 `awaiting_version_approval`로 대기하는지
- [ ] (사전에 목표 스택을 반영한 새 parent 버전을 준비해두고) 다른 값을 입력해 확인 → 진행 로그에 "사내 parent POM 버전을 ...로 교체" 스텝이 맨 먼저 실행되고, 완료 후 "재분석" 로그가 남고, 이어지는 계획이 재분석된 스택 기준으로 세워지는지

### 진행 상황 & 분석 패널 (`index.html` / `job.html` 공유)

- [ ] 1단계 실행 시 "분석" 카드가 진행 상황 아래에 표시되고, 감지된 스택(Java/Spring Boot/Cloud/AI)과 마이그레이션 전 취약점 테이블이 채워지는지
- [ ] 취약점이 있는 job의 `job.html`(1·2단계 모두 선택)에서 네 표(마이그레이션 전 / 마이그레이션 후 / 2단계 패치 대상 / 최종)가 기본 접힌 채로 로드되고, 배지 건수가 표 실제 행 수와 일치하며, 클릭 시 펼쳐지는지
- [ ] `index.html`과 `job.html` 양쪽 모두에서 "진행 상황" 제목 옆 "?" 아이콘 클릭 시 LangGraph 오케스트레이션 모달이 열리고, Stage 1/Stage 2 다이어그램이 잘리거나 겹치지 않고 표시되는지, 닫기 버튼/배경 클릭으로 닫히는지, 다크 모드에서도 색상이 자연스러운지
- [ ] 1단계가 카탈로그에 알려진 레시피 없음(예: Spring Boot 4.0 → 4.1)으로 막히고 2단계도 체크된 채 제출한 경우, 상태 배지가 `awaiting_approval`로 바뀌고 "2단계로 진행(승인)" 버튼이 나타나는지 + 그 시점에 결과물 패널에서 인수인계 가이드를 미리 볼 수 있는지
- [ ] "2단계로 진행" 버튼 클릭 시 버튼이 사라지고, 재연결 없이 2단계 로그가 이어서 표시되며 최종 상태가 `stage1_needs_handoff`(2단계가 문제 없이 끝난 경우 — 1단계 갭이 여전히 남아있다는 뜻) 또는 `stage2_needs_handoff`(2단계도 막힌 경우)로 끝나는지

### 작업 취소

- [ ] `index.html`에서 job 시작 직후 진행 패널에 "중지" 버튼이 보이고, 클릭 시 확인 다이얼로그가 뜨는지 → 확인하면 상태 배지가 `cancelled`로 바뀌고 로그에 남는지
- [ ] `history.html → job.html?job={id}`로 진입한, 아직 실행 중인 job에서도 "중지" 버튼이 똑같이 동작하는지
- [ ] 이미 끝난 job의 `job.html` 상세 페이지에는 "중지" 버튼이 보이지 않는지
- [ ] `backend/data/jobs/{id}/output/CANCELLED` 마커 파일이 생기고, 취소 시점에 실행 중이던 로그 파일(`output/logs/**/*.log`) 끝에 `[강제종료됨]` 줄이 남는지, 실제 `mvn`/`java` 프로세스가 OS에서 종료됐는지(작업 관리자 등으로 확인)
- [ ] 진행 중인 job을 하나 시작해 `history.html`에서 "중지" 버튼이 보이는지, 클릭 후 상태가 `cancelled`로 바뀌면 "삭제" 버튼으로 자동 전환되는지

### 결과물 & 파일별 보기

- [ ] 종료 후 결과물 패널에 diff/report 버튼이 활성화되고, 클릭 시 내용이 보이는지 + 복사/다운로드가 동작하는지
- [ ] `job.html`에서 diff가 있는 job에 "파일별로 보기" 링크가 보이고, 클릭 시 `files.html?job={id}`로 이동하는지
- [ ] `files.html`에서 jsTree 트리가 기본 접힘으로 로드되고 `target/`/`.git` 등이 안 보이며, 폴더가 파일보다 먼저 정렬되고 폴더/파일 아이콘이 표시되는지(개발자 도구 네트워크 탭에서 `assets/vendor/` 아래 jQuery/jsTree/이미지가 모두 200으로 로드되는지도 확인)
- [ ] `files.html`에서 "전체 펼치기"/"전체 접기" 버튼 클릭 시 트리의 모든 폴더가 한 번에 펼쳐지고/접히는지
- [ ] 수정된 파일 클릭 시 좌우에 실제 수정 전/후 코드가 보이는지, 새로 추가된 파일은 왼쪽에 "(새로 추가된 파일)"이 나오는지
- [ ] (가능하면) 바이너리 파일이 포함된 프로젝트로 job을 하나 만들어 "바이너리 파일은 미리볼 수 없습니다" 문구가 뜨는지

### 인수인계 후 재개 (Stage 1)

- [ ] 1단계만 요청한 job이 1단계에서 막혀 상태 배지가 `stage1_needs_handoff`로 끝나면 결과물 패널에 "인수인계 후 재개 (수동 수정 확인)" 버튼이 뜨는지(다른 상태에서는 안 뜨는지)
- [ ] `backend/data/jobs/{id}/work/`를 직접 고친 뒤 버튼 클릭 → 상태가 다시 `running`으로 바뀌고 로그가 이어서 표시되는지, SSE가 재연결되는지(버튼 클릭 전 상태가 터미널이었으므로 연결이 닫혀 있었을 것)
- [ ] 검증(`mvn test-compile`) 통과 + 남은 계획이 없거나 전부 성공 → 최종 `success`로 끝나고, 결과물의 handoff 가이드 버튼 목록에서 1차 시도 때 만들어졌던 가이드가 사라지는지
- [ ] 검증 실패(일부러 컴파일 에러를 남겨둔 채 클릭) → 상태가 다시 `stage1_needs_handoff`로 돌아가고, handoff 가이드 내용이 최신 실패 로그로 갱신되며, 버튼이 다시 나타나 반복 클릭할 수 있는지
